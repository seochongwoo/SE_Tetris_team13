# 아이템 모드 명세 및 설계 정리

요구사항 2(아이템 모드)와 관련해 논의한 내용을 정리한 팀 내부 문서. 평가팀에 제공하는 확정 명세는 [아이템 명세서](item-specification.md)에 있으며, 규칙이 확정되면 두 문서를 함께 갱신한다.
상태 표기: **[확정]** 요구사항에 명시 / **[팀 확정]** 팀에서 합의한 구현 규칙 / **[제안]** 팀 논의 후 확정 필요 / **[예비]** 대체 후보 / **[질문]** 팀 논의로 결정 필요 / **(구현됨)** 현재 코드에 그 방식으로 반영됨

---

## 1. 요구사항에 제시된 아이템

### 공통 [확정]

- 아이템 모드에서는 10개의 줄을 삭제할 때마다 아이템이 등장
- 10줄이 삭제되면 다음 블럭 미리보기에 새로 나타나는 블럭은 반드시 아이템이거나 아이템을 포함
- 블럭의 일부에 아이템이 포함되는 경우와 블럭 자체가 아이템인 경우가 모두 있음
- 아이템은 특징적인 모양이나 기본 블럭과 다른 문자로 표현하고, 아이템마다 반드시 다른 문자 사용
- 제시된 2개 외에 팀이 직접 구상한 아이템을 최소 3개 이상 추가

### 줄 삭제 아이템 (`L`) [확정]

- 기본 블럭 내에 포함되며 문자 `L`로 표시
- 블럭이 더 이상 움직이지 못하면(바닥/다른 블럭에 닿으면) `L`이 위치한 줄을 꽉 차 있지 않아도 삭제
- 블럭에 붙는 위치는 무작위 (예: I형 블럭이면 `OOOL`, `OOLO`, `OLOO`, `LOOO`)
- 아이템으로 삭제된 줄도 기존 방식대로 점수 계산

### 무게추 아이템 [확정]

- 너비 4칸 (요구사항 예시 모양은 위 `OO` / 아래 `OOOO`). 너비가 4칸이면 형태·문자는 자유
- 떨어지면서 밑에 있는 모든 블럭을 지움
- 처음에는 좌우로 이동 가능, 바닥이나 다른 블럭에 닿으면 더 이상 좌우 이동 불가
- 기본적으로 사용이나 지워지는 블럭에 점수 없음 (원하면 적절한 규칙으로 부여 가능)

## 2. 우리 팀 아이템 구성

| 글자 | 아이템    | 형태                        | 효과                                       | 상태 |
| ---- | --------- | --------------------------- | ------------------------------------------ | ---- |
| `L`  | 줄 삭제   | 일반 블럭의 한 칸(무작위)   | 고정 시 해당 줄 삭제                       | [확정] (구현됨) |
| `@`  | 무게추    | 폭 4칸 전용 블럭            | 낙하하며 아래 블럭 모두 제거               | 표시·동작 [팀 확정] (구현됨) |
| `C`  | 연쇄 삭제 | 일반 블럭의 한 칸(무작위)   | 고정 시 맞닿은 같은 종류 블럭 덩어리 삭제  | [팀 확정] (구현됨) |
| `B`  | 폭탄      | 1칸짜리 단독 블럭           | 고정 시 주위 3×3 칸 삭제                   | [팀 확정] (구현됨) |
| `$`  | 점수 2배  | 일반 블럭의 한 칸(무작위)   | 이후 줄 삭제 동작 3번의 점수 ×2           | [팀 확정] (구현됨) |
| `V`  | 세로 삭제 | 일반 블럭의 한 칸(무작위)   | 고정 시 해당 열 전체 삭제                  | [예비] 이번 확정안에 미포함 |

- 대안 후보: 시간 지연 `T`(이후 블럭 10개 동안 낙하 주기 2배, application의 `SpeedPolicy`에 반영), 블럭 리롤 `R`(미리보기 블럭 다시 뽑기, 확률 생성기와 엮여 주의), 빈칸 메우기 `F`
- 팀 아이템은 `C`·`B`·`$`의 현재 형태·기능·점수 규칙으로 확정했다 (2026-10-22, 카드 9~11, `ItemCatalog`에 등록).
- 색이 아니라 **글자**로 구분하므로 색맹 모드와 충돌하지 않는다.
- 화면에서 블럭 한 칸은 글자 2칸으로 그리고 기본 블럭은 칸마다 무늬(`[]`, `##` 등)가 있으므로, 아이템 칸은 문자에 반전 배경을 더해 기본 무늬와 구분한다. 무게추는 모든 칸을 `@@`로 표시하고 반전 배경을 쓰지 않는다 [팀 확정]. 코드·로그의 내부 식별 문자 `W`는 화면 문자 `@`와 구분한다.
- 블럭 일부에 포함되는 아이템(`L`, `C`, `$`)과 블럭 자체가 아이템인 것(`@`, `B`)을 모두 포함한다.

### 무게추(`@`) 동작 구체화 [팀 확정] (구현됨)

- 실제 하강을 시도하다 바닥이나 다른 블럭에 막히기 전까지는 좌우 이동 가능, 회전은 불가. 바로 위로 옆걸음하거나 초기 배치·스폰되는 것만으로는 잠기지 않는다.
- 다음 자동 하강·내리기·한 번에 떨어뜨리기에서 아래 충돌을 확인하면 좌우 이동을 잠근다. 충돌 판정 후 아래 4칸 폭의 블럭을 지우며 내려가고, 아래가 다시 비어도 잠금은 유지한다. 바닥에 막힌 하강 시도에서는 즉시 고정한다. 이동 유예는 고정된 1초가 아니라 다음 하강 시도까지다.
- 요구사항 예시 화면처럼 고정된 무게추는 일반 칸으로 보드에 남음
- 지운 칸과 무게추의 하강 거리에는 점수 없음. 고정 후 꽉 찬 줄이 생기면 일반 줄 삭제 점수는 적용
- 구현: `WeightBlock`은 `ItemKind`·`Item`을 구현하고 전용 `SHAPE`(위 2칸/아래 4칸, 회전 상태 1개)의 `movementRule()`에서 `WeightMovementRule`을 반환한다. `PlayerEngine.descendOneCell`이 칸을 지우기 전에 `updateContact`로 실제 하강 시도의 충돌을 기억하며, `WeightMovementRule.allowsHorizontalMovement`는 그 이후 좌우 이동을 막고 `allowsRotation`은 항상 회전을 막는다. 이어서 `DropRule.descend` → `WeightMovementRule.descend` 순서로 다음 위치의 칸을 지우고 한 칸 내려간다. 낙하 거리는 그대로 보고하며, `SinglePlayerSession`은 동작 전 블록이 무게추일 때 하강 점수를 제외한다.

### 연쇄 삭제(`C`) 구현 메모 [팀 확정]

- 알고리즘: 상하좌우 4방향 BFS로 **블럭 모양(`Cell.occupiedBy()`)이 같은** 칸을 수집 (15줄 안팎). 블럭 모양은 이미 칸에 저장돼 있어 데이터 추가는 필요 없음.
- 변경 범위: `core/item/`에 아이템 클래스 1개. 효과에 필요한 칸 조회(`ItemContext.cellAt`)와 칸 단위 삭제(`ItemContext.removeCell`)는 이미 있으므로 `Board` 변경도 필요 없음. 효과로 지운 칸은 점수가 없으므로 `application`도 변경 없음.
- 확정 규칙:
  1. 기준 단위: `Cell`에 블럭 개체 ID가 없으므로 "같은 종류로 이어진 덩어리"로 정의 (서로 다른 두 T가 맞닿아도 한 덩어리)
  2. 테트로미노가 아닌 칸(고정된 무게추 등): `occupiedBy()`가 `TetrominoType`이 아니므로 덩어리에 포함하지 않음
  3. 자기 블럭 포함 여부: 같은 종류의 이웃이 있을 때만 지우며, 이때 자기 블럭도 포함
  4. 지운 뒤 처리: 위 블럭은 떨어뜨리지 않고 그대로 둔다
- 구현됨 (`ChainClearItem`): 덩어리 크기가 자기 블럭 칸 수(4)보다 클 때만 지우며, 이때 자기 블럭도 함께 지워진다.

### 폭탄(`B`) 구현 메모 [팀 확정] (구현됨)

- `BombItem` + `SoloBlock`: 아이템 차례가 되면 원래 나올 일반 블럭 대신 1칸짜리 블럭이 나온다. 회전 상태가 하나라 회전하지 않고, 좌우 이동·내리기는 일반 블럭과 같다.
- 고정되면 자기 칸 중심 3×3(자기 칸 포함)을 지운다. 보드 밖은 무시하고, 지운 칸 위의 블럭은 떨어뜨리지 않는다. 지운 칸에는 점수 없음.

### 점수 2배(`$`) 구현 메모 [팀 확정] (구현됨)

- `DoubleScoreItem`은 보드에 아무것도 하지 않고, `SinglePlayerSession`이 발동 보고(`itemActivations`)를 보고 처리한다.
- 적용 범위: `$`가 붙은 블럭이 고정된 그 동작부터, 줄을 지운 동작 3번. 줄을 지우지 않은 고정은 횟수를 쓰지 않는다.
- 2배 대상은 그 동작의 점수 전체(하강 점수 + 줄 삭제 점수).
- 중복 획득: 남은 횟수를 3으로 다시 채운다 (누적하지 않음).
- 화면: 남은 횟수가 있으면 SCORE 옆에 `x2 (남은 횟수)`를 표시한다.

### 공통 규칙 [팀 확정]

- **발동 순서**: 블럭 고정(보드에 기록) → 아이템 효과 → 일반 줄 삭제 판정 (구현됨). 단, 무게추는 고정 시점이 아니라 낙하 중에 효과가 발생
- **점수**: 아이템 효과로 지운 칸에는 점수 없음. 단, `L`로 삭제된 줄은 요구사항대로 기존 방식으로 점수 계산
- **같은 고정에서 함께 지워진 줄**: `L`로 지운 줄과 꽉 차서 지운 줄은 합쳐서 한 번의 줄 삭제로 계산 (기존 동시 삭제 보너스 그대로 적용) (구현됨: 같은 `ClearResult`로 보고, 겹치는 줄은 한 번만 셈)
- **아이템 소모**: 모든 아이템은 고정 시 한 번 발동하고 소모됨. 보드 칸에는 아이템 표시를 남기지 않음 (`L`·`B`는 자기 칸도 함께 지워지고, `C`·`$`도 발동 후 일반 칸이 됨). 무게추의 `@`는 블럭 모양을 나타내는 무늬라 고정 후에도 유지 (구현됨)
- **아이템 선택**: 아이템이 등장할 때 최종 아이템 중 하나를 균등 확률로 선택. 블럭에 붙는 아이템이면 붙을 블럭과 칸 위치도 무작위 (구현됨: `ItemPieceSource`, `AttachedItem`)
- **등장 기준**: 게임 전체 누적 삭제 줄 수가 10, 20, 30…을 넘을 때마다 한 개. 한 번에 두 기준을 넘으면 두 블럭 연속으로 아이템. `L` 등 아이템으로 지운 줄도 줄 수에 포함 (구현됨, 10-23 팀 확정, [미확정 사항](open-questions.md) 안건 ⑥)
- **회전**: 블럭에 붙은 아이템은 블럭과 함께 회전 (구현됨: 회전해도 같은 칸 번호가 같은 칸을 가리킴). 블럭 자체가 아이템인 `@`·`B`는 회전 불가 (`rotationStates()`를 1로 두면 됨)
- **지속 효과 기준**: 시간(초)이 아니라 횟수(줄 N번, 블럭 N개)로 정의 → 일시정지 영향이 없고 테스트가 결정적
- **중복 획득**: `$`는 남은 횟수를 3으로 리셋하며 누적하지 않음 (구현됨)

## 3. 추가·수정 파일 (요약)

- **core**
  - 구현됨 (카드 1): `Shape`(블럭 모양), `Piece`(모양 + 칸별 아이템), 아이템을 담는 `Cell`, `item/Item`·`item/ItemContext`(고정 시 효과), `rule/PieceSource`·`rule/PlainPieceSource`(아이템 공급과 지운 줄 수 알림), `ClearedRow`의 지운 칸 내용, `EngineStep.itemActivations()`
  - 구현됨 (카드 6): `rule/ItemPieceSource`(10줄마다 아이템, 일반 공급자를 감싸는 형태), `item/ItemKind`·`item/AttachedItem`(아이템이 블럭에 실리는 방식), `item/ItemCatalog`(등장 아이템 목록, 새 아이템은 여기에 한 줄 추가)
  - 구현됨 (카드 3): `rule/WeightedRandomGenerator`(7-bag 대체, 블럭별 가중치를 생성자로 받음), 난이도별 가중치는 application의 `PieceWeightPolicy`
  - 구현됨 (카드 9~11): `item/ChainClearItem`(`C`), `item/BombItem`(`B`)·`item/SoloBlock`(1칸 블럭), `item/DoubleScoreItem`(`$`, 점수 처리는 `SinglePlayerSession`)
  - 구현됨 (카드 7~8): `item/LineClearItem`(`L`), `item/WeightBlock`(화면 `@`, 내부 식별 `W`), `PlayerEngine`의 하강 시도 중 충돌 이력 관리, `item/WeightMovementRule`의 충돌 후 이동 제한·낙하 삭제, `SinglePlayerSession`의 무게추 하강 점수 제외
- **application**: `Difficulty`, `GameMode`, `Settings`(난이도), `GameResult`·`ScoreEntry`(모드·난이도), `ScoreboardService`(모드·난이도별 순위), `SpeedPolicy`(난이도별 증가율), `ApplicationContext.newGame`(모드·난이도 전달), `SinglePlayerSession`(줄 삭제 애니메이션 동안 대기, `$` 같은 보드 밖 아이템 효과)
- **storage**: `PropertiesSettingsRepository`(설정 파일 `schemaVersion` 2), `BinaryScoreRepository`(점수 파일 버전 2, 기존 기록은 일반 모드·normal로 변환)
- **bootstrap**: `AppComposition`(모드·난이도에 맞는 생성기·공급자·규칙 조립)
- **ui**: 메뉴 항목, 설정 화면 난이도 줄, 다음 블럭 아이템 표시와 아이템 글자 렌더링(구현됨), 줄 삭제 애니메이션, 스코어보드 모드·난이도 구분
- **docs**: 이 문서

`Difficulty`와 `GameMode`는 설정·스코어보드에서 쓰는 개념이라 core가 아니라 application에 둔다. core는 난이도를 모르고 블럭별 가중치만 받는다 (`SpeedPolicy`를 application에 둔 기존 결정과 같은 원칙).

## 4. 테스트 계획

| 대상 | 케이스 |
| ---- | ------ |
| `L` 줄 삭제 | `L`이 있는 줄만 삭제, 꽉 차지 않은 줄 삭제, 삭제된 줄 점수 계산, 꽉 찬 줄과 동시 삭제 시 합산 |
| `L` 위치 | 시드를 바꿔 반복하면 블럭의 모든 칸 위치에 붙음 |
| 무게추 | 블럭·바닥 바로 위에서도 하강 시도 전까지 좌우 이동 가능, 하강 시 충돌 후 잠금 유지, 회전 불가, 아래 블럭 전부 제거, 바닥에서 고정 후 `@` 무늬 유지, 점수 없음 |
| `C` 연쇄 삭제 | 이웃 없음, 같은 종류 덩어리, 종류가 다른 이웃, 대각선 비연결, 보드 가장자리 |
| `B` 폭탄 | 중앙, 보드 가장자리, 모서리에서 3×3 범위 |
| `$` 점수 2배 | 3번 후 원복, 중복 획득 규칙 |
| 아이템 등장 | 10줄 삭제 시 다음 블럭이 아이템, 미리보기 반영, 아이템마다 다른 문자 |
| 가중치 생성 | 최소 1,000회 선택, 설정 확률 대비 오차 ±5% 이내, 실제 게임 생성 코드로 검증. easy/hard는 I블럭 가중치 12/8(다른 블럭 10) → I 확률 약 16.7%/11.8% |
| 난이도 속도 | 줄 삭제에 따른 속도 증가율이 easy는 20% 덜, hard는 20% 더 |

아이템 공통 구조(발동 순서, 줄 일괄 삭제, 회전 시 칸 추적, 칸 단위 삭제, 지운 줄 수 알림)는 카드 1에서 테스트용 아이템으로 이미 검증함 (`PlayerEngineTest`, `BoardTest`, `PieceTest`).

## 5. 열린 질문

남은 질문 없음. e-class에 문의하지 않고 팀 내부 논의로 정했으며, 안건별 원문·현재 구현·결정은 [미확정 사항](open-questions.md)의 "2차 요구사항 팀 논의 안건"에 있습니다. 2026-10-23에 아래 세 가지를 현재 구현대로 확정했습니다.

- 난이도(easy/normal/hard)는 아이템 모드에도 적용하고, 스코어보드는 모드 × 난이도로 구분 (안건 ⑤)
- "10줄 삭제" 카운트에 `L` 등 아이템으로 지운 줄도 포함하고 게임 전체로 누적 (안건 ⑥)
- 무게추가 지운 칸·하강 거리는 0점, 무게추가 고정되며 꽉 찬 줄은 일반 줄 삭제 점수 (안건 ⑦)

## 6. 팀 결정 완료 (2026-10-22)

- 자체 아이템은 `C`·`B`·`$` 세 가지와 현재 세부 규칙으로 확정. `V`는 확정안에 포함하지 않음.
- 무게추 화면 문자는 `@`(한 칸당 `@@`), 형태는 위 2칸/아래 4칸으로 확정. 내부 식별 문자 `W`와 구분.
- 무게추는 실제 하강 시도에서 아래 블럭·바닥에 막힌 시점부터 좌우 잠금. 초기 배치·스폰·옆걸음만으로 잠그지 않음.
- `$` 재획득 시 남은 적용 횟수는 3으로 리셋. 나머지 세부 동작은 2장과 [평가용 명세서](item-specification.md)를 기준으로 함.
