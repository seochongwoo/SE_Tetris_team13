# 미확정 사항

이 문서는 게임 요구사항을 충족하기 위해 결정하거나 검증할 항목을 정리합니다. 필수 조건과 현재 구현의 기본값은 구분하며, 별도 설계 제안의 수치·구조를 필수 조건으로 취급하지 않습니다. 세부 구현 계약은 [개발 가이드](developer-guide.md)에서 관리합니다.

- 가속 조건: 1차 p8 "일정 수 이상의 블럭이 생성되거나, 줄이 삭제되면"은 둘 중 하나로 충족되며, 2차 p3도 "줄 삭제에 따라 증가하는 속도"를 전제로 합니다. 10줄마다 가속을 유지합니다.

안건 9개는 2026-10-23까지 모두 결정했습니다. 새 안건이 생기면 이 표에 추가하고, 결정이 나면 결정 칸에 날짜와 결과를 적고 [아이템 명세서](item-specification.md), [아이템 모드 설계 정리](item-spec.md), [요구사항 추적표](requirements-traceability.md)를 함께 고칩니다. 2차 요구사항(난이도, 아이템 모드)의 진행 상황은 [백로그 진행 현황](requirements2-backlog.md), 아이템 관련 열린 질문은 [아이템 모드 명세](item-spec.md)의 5장에서 관리합니다.

숫자나 방식이 지정되지 않은 세부 사항은 위 조건을 충족하는 범위에서 정합니다. 현재 코드의 정책값은 합의 완료를 뜻하지 않습니다. 자동 테스트와 실제 화면 검증 절차는 [개발 가이드의 빌드·테스트 절](developer-guide.md#10-빌드테스트)을 참고하세요.

### N3-01 측정 절차 (2026-11-07 확정)

요구사항: 같은 로컬 네트워크에서 키 입력과 화면 표시 사이 지연 200ms 이하 (3차 p9)

| 항목 | 결정 |
| --- | --- |
| 측정 구간 | A PC의 키 입력 → B PC 화면에 그 변화가 그려짐 |
| 시작점·완료점 | A가 키 이벤트를 받은 시각 → B가 그 변화를 반영한 화면을 그린 시각 |
| 측정 방법 | B가 화면을 그린 직후 A에 확인 메시지를 보내고, A의 시계로 키 입력부터 확인 수신까지의 왕복 시간을 잼. 왕복이 200ms 이하이면 편도도 200ms 이하이므로 두 PC의 시계를 맞추지 않음. 휴대폰 고속 촬영(240fps)으로 몇 번 대조 |
| 조작과 횟수 | 이동, 회전, 한 번에 떨어뜨리기 각 50회 × 양방향 = 300회 |
| 판정 | 최댓값이 200ms 이하이면 통과. 평균만으로 통과시키지 않고, 200ms 초과 횟수와 95% 값도 기록 |
| 기록 | 빌드 버전, PC 사양, 네트워크(유선·Wi-Fi), 모드, 방향, 표본 수, 최대·95%·평균, 초과 횟수 |
| 측정 기능 | 디버그 모드에서만 켬 |
