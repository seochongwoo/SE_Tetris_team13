# 미확정 사항

이 문서는 게임 요구사항을 충족하기 위해 결정하거나 검증할 항목을 정리합니다. 필수 조건과 현재 구현의 기본값은 구분하며, 별도 설계 제안의 수치·구조를 필수 조건으로 취급하지 않습니다. 세부 구현 계약은 [개발 가이드](developer-guide.md)에서 관리합니다.

## 구현 상태와 남은 확인

| 항목                | 충족해야 할 조건                                                                                                                                                 | 현재 상태와 결정·확인할 내용                                                                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시작 메뉴           | 게임 이름, 시작·설정·스코어보드·프로그램 종료 메뉴, 키보드 이동과 선택, 메뉴 확장 가능 구조                                                                      | Swing 시작 화면 구현. 메뉴 항목 목록으로 확장하며 ↑↓ 이동·Enter 선택을 화면에 안내.                                                                                 |
| 게임 화면           | 20줄×10칸 보드, 다음 블록 표시, 실시간 점수 표시                                                                                                                 | 10×20 보드·다음 블록·실시간 점수를 문자 프레임으로 표시하고 테스트.                                                                                                 |
| 블록 추첨           | 7가지 블록이 동일한 확률로 무작위 등장                                                                                                                           | 해결됨: 2차에서 매번 독립적으로 뽑는 가중치 생성기로 교체. normal 난이도는 일곱 종류 모두 1/7.                                                                                                           |
| 낙하·조작·정지      | 초기 1초당 1칸 낙하, 일정 블록 수 또는 삭제 줄 수 이후 가속, 좌우·아래 이동·시계방향 90도 회전·즉시 낙하, 반복 입력의 즉각적 반응, 정지·재개와 진행·정지 중 종료 | 초기 1초, 10줄마다 가속·최소 100ms. 조작·반복·정지·재개·종료 구현 및 테스트. 재개/게임 메뉴 키와 충돌하면 메뉴 이동·선택에 대체 키를 안내. 가속 수치는 팀 합의 확인 |
| 점수                | 자동·수동 하강 모두 칸당 기본 점수, 가속 시 추가 점수, 별도의 점수 방식 최소 1개, 실시간 표시                                                                    | 하강 거리×(레벨+1), 100×삭제 줄 수² 보너스와 화면 갱신 구현·테스트. 구체 공식의 팀 합의 확인                                                                        |
| 블록 구분·색맹 모드 | 블록별 다른 색상, 유사한 모양의 구분, 색맹 모드에서 적록·청황 색각 이상 모두 고려                                                                                | 기본/색맹 팔레트와 7종류 문자 무늬 구현·테스트.                                                                                                                     |
| 화면 크기·키 설정   | 최소 3가지 화면 크기와 게임 조작 키 변경                                                                                                                         | 14/18/24px 글꼴로 창 크기 변경, AWT 키 변환과 설정 화면 연결 완료.                                                                                                  |
| 설정 저장·초기화    | 변경 설정을 다음 실행에서 복원, 기본 설정 복원, 스코어보드 초기화 제공                                                                                           | 설정 화면의 즉시 저장·기본값 복원·기록 초기화와 파일 저장소 테스트 구현.                                                                                            |
| 게임 종료 흐름      | 더 이상 쌓을 수 없으면 종료, 순위 기록 대상이면 이름 입력, 저장 후 새 이름·점수 강조, 이후 메뉴 복귀 또는 프로그램 종료                                          | GAME OVER → 필요시 이름 입력 → 기록 강조 → 메뉴 복귀/프로그램 종료 연결 및 화면 로직 테스트 완료                                                                    |
| 순위와 기록 유지    | 이름·점수를 점수 내림차순 표시, 적어도 상위 10개 보관, 초기화 전까지 재실행 후에도 기록 유지                                                                     | 점수 내림차순 상위 10개, 파일 저장·초기화 및 화면 로직 테스트 구현.                                                                                                 |
| 실행 환경·성능      | Java 21 이상, Windows 11 또는 macOS 26 이상 중 대상 환경, 1.2GHz 이상 CPU·1GB RAM·500MB 여유 공간에서 원활한 실행                                                | Windows 대상. ResponsivenessTest는 업데이트·문자 프레임 평균 4ms 미만 등을 검사. Windows 11 최소 사양 플레이, 디스크 사용량은 미검증                                |
| 코드 검증           | 직접 작성한 코드의 Line Coverage 50~70% 이상, 비기능 요구사항 검증 테스트 최소 1개, 변경 시 쉽게 테스트 실행·커버리지 관리                                       | JUnit·JaCoCo·Windows CI와 비기능 테스트 구현. 커버리지 하한은 빌드에서 강제하지 않음                                                                                |
| 배포                | 손쉬운 패키지 생성, 아이콘 포함 실행파일, 더블클릭 등으로 추가 명령·설정 없이 실행                                                                               | packageZip으로 아이콘·JRE 포함 Windows exe 패키지를 생성하도록 구성. Windows 패키지 생성·더블클릭 실행은 검증 필요; CI는 패키지 생성 미포함                         |

숫자나 방식이 지정되지 않은 세부 사항은 위 조건을 충족하는 범위에서 정합니다. 현재 코드의 정책값은 합의 완료를 뜻하지 않습니다. 자동 테스트와 실제 화면 검증 절차는 [개발 가이드의 빌드·테스트 절](developer-guide.md#10-빌드테스트)을 참고하세요.
