# 미확정 사항

이 문서는 게임 요구사항을 충족하기 위해 결정하거나 검증할 항목을 정리합니다. 필수 조건과 현재 구현의 기본값은 구분하며, 별도 설계 제안의 수치·구조를 필수 조건으로 취급하지 않습니다. 세부 구현 계약은 [개발 가이드](developer-guide.md)에서 관리합니다.

## 2차 요구사항 팀 논의 안건 (2026-10-22)

요구사항 원문(1차 19쪽, 2차 12쪽)과 구현을 다시 대조하면서 해석이 갈리는 부분을 정리했습니다. 원문은 모호한 부분을 e-class에 문의하도록 안내하지만, 아래 항목은 팀 내부 논의로 정하고 결정과 근거를 이 표에 남깁니다. 결정 칸이 비어 있으면 아직 논의 중입니다.

| # | 안건 | 원문 | 현재 구현 | 제안 | 결정 |
| --- | --- | --- | --- | --- | --- |
| ① | 줄 삭제 연출 중 누른 키 | 1차 p8 "반복된 키 입력이 무시되지 않고 블럭이 즉시, 정확하게 반응" | 연출(300ms) 중 이동·회전 키를 버림 | 키를 모아 두었다가 연출이 끝난 뒤 순서대로 처리 | |
| ② | 무게추 표시 문자 | 2차 p7 "각각의 아이템은 반드시 다른 문자", p9 "너비가 4칸이면 어떤 형태나 문자를 사용해도 좋습니다" | 모든 칸 `@@`, `W`는 표시하지 않음 (`@`는 무게추만 사용) | `@` 무늬로 확정하고 문서 통일 | |
| ③ | 무게추가 "닿았다"고 보는 시점 | 2차 p9 "일단 바닥이나 다른 블럭에 닿으면 더 이상 좌우로는 움직이지 못합니다" | 바로 아래에 블록이 오는 순간 잠금 (아래 키를 누르지 않아도) | 현재 방식으로 확정 | |
| ④ | 팀 아이템 `C`·`B`·`$` 규칙 | 2차 p10 팀 아이템 명세서를 평가팀에 제공 | [아이템 명세서](item-specification.md) 4장 규칙으로 구현 | 현재 규칙으로 [확정] | |
| ⑤ | 아이템 모드의 난이도 | 2차 p3 "기존의 일반 게임 모드에 난이도 설정을 추가" | 아이템 모드에도 적용, 스코어보드 모드 × 난이도 | 유지 (원문이 아이템 모드 적용을 막지 않음) | |
| ⑥ | 아이템으로 지운 줄의 10줄 카운트 | 2차 p7 "10개의 줄을 삭제할 때마다", p8 "기존의 방식대로 점수를 계산" | 포함, 게임 전체 누적 | 유지 | |
| ⑦ | 무게추가 고정되며 생긴 줄 삭제의 점수 | 2차 p9 "사용이나 지워지는 블럭 등에 대해서는 점수를 부여하지 않습니다" | 무게추가 지운 칸·하강 거리는 0점, 고정 후 꽉 찬 줄은 일반 줄 삭제 점수 | 유지 | |
| ⑧ | 다음 블록 미리보기 개수 | 1차 p7 "다음에 생성될 블럭들을 표시" | 1개 (원문 예시 화면과 같음) | 유지 | |
| ⑨ | 난이도별 속도 증가 ±20%의 기준 | 2차 p3 "easy에서는 20% 덜 증가하고, hard에서는 20% 더 증가" | 레벨당 낙하 간격 감소량 80/100/120ms, 최소 간격 100ms는 공통 | 유지 | |

원문과 대조해 해석 문제가 없다고 확인한 항목:

- I블록 ±20%: 2차 p4가 "다른 블럭의 등장확률 가중치가 10이라고 할 때 I형 블럭은 12"로 방법까지 제시하며, 구현(12/10/8)이 이와 같습니다.
- 가속 조건: 1차 p8 "일정 수 이상의 블럭이 생성되거나, 줄이 삭제되면"은 둘 중 하나로 충족되며, 2차 p3도 "줄 삭제에 따라 증가하는 속도"를 전제로 합니다. 10줄마다 가속을 유지합니다.

결정이 나면 결정 칸에 날짜와 결과를 적고, [아이템 명세서](item-specification.md), [아이템 모드 설계 정리](item-spec.md), [요구사항 추적표](requirements-traceability.md)를 함께 고칩니다. 2차 요구사항(난이도, 아이템 모드)의 진행 상황은 [백로그 진행 현황](requirements2-backlog.md), 아이템 관련 열린 질문은 [아이템 모드 명세](item-spec.md)의 5장에서 관리합니다.

숫자나 방식이 지정되지 않은 세부 사항은 위 조건을 충족하는 범위에서 정합니다. 현재 코드의 정책값은 합의 완료를 뜻하지 않습니다. 자동 테스트와 실제 화면 검증 절차는 [개발 가이드의 빌드·테스트 절](developer-guide.md#10-빌드테스트)을 참고하세요.
