# 미확정 사항

이 문서는 게임 요구사항을 충족하기 위해 결정하거나 검증할 항목을 정리합니다. 필수 조건과 현재 구현의 기본값은 구분하며, 별도 설계 제안의 수치·구조를 필수 조건으로 취급하지 않습니다. 세부 구현 계약은 [개발 가이드](developer-guide.md)에서 관리합니다.

## 결정할 항목

| 항목                | 충족해야 할 조건                                                                                                                                                 | 현재 상태와 결정·확인할 내용                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 시작 메뉴           | 게임 이름, 시작·설정·스코어보드·프로그램 종료 메뉴, 키보드 이동과 선택, 메뉴 확장 가능 구조                                                                      | 실제 UI 미연결. 화면 구성과 메뉴 확장 방식을 정하고 Enter 이외의 선택 키를 사용하면 화면에 안내 |
| 게임 화면           | 20줄×10칸 보드, 다음 블록 표시, 실시간 점수 표시                                                                                                                 | 기본 보드는 10×20이고 다음 블록·점수 데이터를 제공. 실제 표시와 갱신 확인                       |
| 블록 추첨           | 7가지 블록이 동일한 확률로 무작위 등장                                                                                                                           | 현재 7-bag 사용. 매 추첨의 동일 확률 조건을 충족하는지 확인하고 필요하면 생성 방식 수정         |
| 낙하·조작·정지      | 초기 1초당 1칸 낙하, 일정 블록 수 또는 삭제 줄 수 이후 가속, 좌우·아래 이동·시계방향 90도 회전·즉시 낙하, 반복 입력의 즉각적 반응, 정지·재개와 진행·정지 중 종료 | 세션 API 제공. 가속 기준과 조작 키를 정하고 실제 UI에서 반응·상태 전환 검증                     |
| 점수                | 자동·수동 하강 모두 칸당 기본 점수, 가속 시 추가 점수, 별도의 점수 방식 최소 1개, 실시간 표시                                                                    | 하강·레벨 보너스와 줄 삭제 보너스 구현. 구체 공식 수용 여부와 화면 반영 확인                    |
| 블록 구분·색맹 모드 | 블록별 다른 색상, 유사한 모양의 구분, 색맹 모드에서 적록·청황 색각 이상 모두 고려                                                                                | 모드 설정값 저장 제공. 실제 색상·무늬와 구분 가능성 확인                                        |
| 화면 크기·키 설정   | 최소 3가지 화면 크기와 게임 조작 키 변경                                                                                                                         | SMALL/MEDIUM/LARGE와 키 매핑 제공. 실제 표시 크기와 사용 가능한 키·이벤트 변환 결정             |
| 설정 저장·초기화    | 변경 설정을 다음 실행에서 복원, 기본 설정 복원, 스코어보드 초기화 제공                                                                                           | 저장·초기화 API 제공. 설정 화면 연결과 재실행 후 복원 확인                                      |
| 게임 종료 흐름      | 더 이상 쌓을 수 없으면 종료, 순위 기록 대상이면 이름 입력, 저장 후 새 이름·점수 강조, 이후 메뉴 복귀 또는 프로그램 종료                                          | 종료 조율자 제공. 이름 입력·강조 표시와 종료 후 이동 화면 연결·검증                             |
| 순위와 기록 유지    | 이름·점수를 점수 내림차순 표시, 적어도 상위 10개 보관, 초기화 전까지 재실행 후에도 기록 유지                                                                     | 기본 상위 10개와 파일 저장 구현. 목록 표시·등록·초기화·재실행 검증                              |
| 실행 환경·성능      | Java 21 이상, Windows 11 또는 macOS 26 이상 중 대상 환경, 1.2GHz 이상 CPU·1GB RAM·500MB 여유 공간에서 원활한 실행                                                | 대상은 Windows. 해당 사양에서 실행과 플레이 성능을 검증할 환경·측정 방법 결정                   |
| 코드 검증           | 직접 작성한 코드의 Line Coverage 50~70% 이상, 비기능 요구사항 검증 테스트 최소 1개, 변경 시 쉽게 테스트 실행·커버리지 관리                                       | JUnit·JaCoCo·CI 구성. 커버리지 충족 여부, 비기능 검증 대상과 합격 기준 확인                     |
| 배포                | 손쉬운 패키지 생성, 아이콘 포함 실행파일, 더블클릭 등으로 추가 명령·설정 없이 실행                                                                               | Gradle 배포물 생성 구성. Windows 실행파일·아이콘·실제 실행 방식 결정 및 검증                    |

숫자나 방식이 지정되지 않은 세부 사항은 위 조건을 충족하는 범위에서 정합니다. 현재 코드의 정책값은 합의 완료를 뜻하지 않습니다. 자동 테스트와 실제 화면 검증 절차는 [개발 가이드의 빌드·테스트 절](developer-guide.md#10-빌드테스트)을 참고하세요.
